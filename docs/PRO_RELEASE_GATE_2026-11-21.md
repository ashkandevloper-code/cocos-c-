# NEXORA PRO — دروازهٔ انتشار ۲۰۲۶-۱۱-۲۱

**وضعیت: نامزدِ بررسی، نه انتشار نهایی.** شاخهٔ `arena/5a4e2a12-cocos-c`، نخستین commit بررسی `61a55d2`. هیچ migration یا Edge Function در این نوبت روی پروژهٔ زنده اعمال/منتشر نشده است. آزمون دستگاه واقعی، اعتبارسنجی Supabase و QA ضدتقلب انجام نشده‌اند. در محیط عامل، اتصال Supabase برقرار نیست و Supabase CLI، `psql` و اعتبارنامهٔ استقرار وجود ندارد. از نتیجهٔ ساختِ قبلی روی `main` نمی‌توان وضعیت این شاخه را نتیجه گرفت.

## دامنهٔ قابل بازبینی

- Finger Soccer، تب «اختصاصی»: حقِ استفادهٔ یک‌باره از تیم عکس‌دار با **۱۰۰۰ جم**؛ پرداخت از `nx_buy_with_gems` با قیمت ثابت در **catalog/constraint سرور**، بدون ارسال قیمت توسط برنامه. عکس از گالری مرکز-بُریده، PNG با اندازهٔ ۲۵۶×۲۵۶ و حداکثر ۱ MiB می‌شود. Bucket جداگانهٔ عمومی `nx-fs-teams` فقط آپلود/تعویض `uid/team.png` توسط صاحبِ حق را مجاز می‌کند؛ RPC `nx_fs_custom_status` مالکیت و نسخهٔ واقعی عکس را برمی‌گرداند. نسخهٔ فایل برای کش استفاده می‌شود و کپی محلی فقط برای همان حساب/نسخه قابل استفاده است. تیم صرفاً ظاهری است و دقیقاً قدرت/دقت تیم رایگان Persepolis (۶/۷) را دارد.
- **فعلاً فقط بازی محلی/ربات پس از تأیید سرور:** خرید و انتخاب عکس در گزینش تیم آنلاین غیرفعال است؛ migration بازی‌ها نیز انتخاب `custom:` را در room prefs و حرکت‌های `setup`/`tpick` رد می‌کند. این محدودیت عمدی است: دیتابیس بازی‌ها به فهرست خریدهای محافظت‌شدهٔ پروژهٔ اصلی دسترسی ندارد. بدون اعتبارسنجی امن بین دو پروژه، ادعای مجوزِ آنلاین نادرست است. عکس‌ها عمومی‌اند؛ سیاست بررسی محتوای بارگذاری‌شده هنوز برای عرضهٔ عمومی لازم است.
- بازخورد صدا و لرزش در بازی‌ها از تنظیمات مستقل استفاده می‌کند. نتیجهٔ آنلاین تا تأیید پایان توسط سرور به‌عنوان پاداش/رکورد قطعی نمایش یا ثبت نمی‌شود. این **بازپخش و اعتبارسنجی قواعد هر بازی روی سرور نیست**؛ توافق گزارش بازیکنان به تنهایی دفاع کامل در برابر تقلب نیست.
- هفت بازی آرکید جدید قابل اجرا از ۱۳ شناسهٔ صرفاً برنامه‌ریزی‌شده جدا شده‌اند؛ دستاورد «همهٔ آرکیدها» هفت بازی موجود را می‌شمارد. شناسه‌های قدیمی دستاوردهای برنامه‌ریزی‌شده برای سازگاری حفظ، اما از فهرست قابل کسب پنهان شده‌اند.

## فهرست بازی‌ها و معیار ادعای کیفیت

رجیستری **۱۶ بازی قابل اجرا** دارد: Finger Soccer، Carrom، Billiards، Backgammon، Ludo، Snakes & Ladders، UNO، Quiz، Mafia، Kart Racing، Obstacle Race، Bomb Arena، Pool 8، Mini Golf، Basketball Battle و Spy Mafia. ۱۳ شناسهٔ آرکید دیگر فقط طراحی/فراداده دارند و بازی اجرایی یا صندلی مسابقهٔ آنلاین نمی‌گیرند. migration `20261121110000_g_registered_game_seats.sql` سقف **صندلی بازیکن فعال** را بر حسب بازی تعیین می‌کند؛ اعضای اجتماعی اتاق و تماشاگر را نباید با صندلی یکی گرفت یا ظرفیت نامحدود واقعی سرور ادعا کرد. صرف وجود تست‌های واحد در `test/games/` برای تأیید قوانین، فیزیک، بازپخش و تجربهٔ دستگاه هر ۱۶ بازی کافی نیست.

سه Edge Function موجود `supabase/functions/{nx-call-token,nx-login,nx-oracle}` باید **در پروژهٔ اصلی** مستقر و با JWT کاربر واقعی، مجوزهای room/seat، ورود امن و محدودیت/پیکربندی Oracle به‌صورت end-to-end بررسی شوند. وجود فایل تابع، کلید عمومی یا اجرای موفق Android، مدرک استقرار نیست. هر تابع/secret را از داشبورد/CLI مجاز در محیط امن بررسی کنید؛ از درخواست یا درج رمز در گفتگو خودداری کنید.

## معیارهای بسته‌شدن قبل از release

1. CI این شاخه: Analyze بدون خطای کامپایل، همهٔ تست‌های Flutter موفق، APK امضاشده قابل نصب و یکسان‌بودن گواهی امضا با نسخهٔ فعلی؛ اجرای workflow با `release_tag` خالی **نباید release منتشر کند**. لینک بررسی: https://github.com/ashkandevloper-code/cocos-c-/actions/runs/44909938956 (نتیجه هنگام نوشتن این سند هنوز معلوم نبود).
2. Staging مستقل برای هر پروژه: مقایسهٔ migration history، اجرای کنترل‌شدهٔ SQL، تست‌های SQL، تست خرید با حساب‌های ۹۹۹/۱۰۰۰ جم، خرید تکراری بدون کسر دوباره، عدم تغییر قیمت از سمت client/admin، آزمون نفوذِ RLS روی آپلود پیش از خرید، آپلود به مسیر حساب دیگر، تعویض عکس و سلب مجوز، و بازخوانی موجودی/عکس از دستگاه دوم. تست‌های schema موجود فقط پیکربندی را می‌سنجند، این سناریوهای تراکنشی را نه.
3. بازی آنلاین: تست دو دستگاه/قطع اتصال/بازیابی log و settlement برای تک‌تک بازی‌های قابل اجرا، نتایج متناقض و پیشگیری از دستکاری move/seat و پاداش؛ برای فعال‌کردن تیم عکس‌دار آنلاین، تأیید مجوز در **سرور بازی** از پروژهٔ اصلی باید طراحی/تست شود. تا آن زمان guard آنلاین حذف نشود.
4. دستگاه واقعی Android: گالری/مجوزها، نمایش PNG در زمین و پنجرهٔ انتخاب، اجرا بدون شبکه پس از همگام‌سازی، مصرف حافظه/نرخ فریم/صدا/لرزش، پایداری تماس و تورنمنت. برای عکس عمومی سیاست مدیریت/گزارش محتوای نامناسب لازم است.
5. تنها پس از تأیید استقرار هر دو پروژه و سه تابع، نتیجهٔ QA و موافقت انتشار، workflow انتشار با tag مشخص اجرا شود؛ artifact و لینک release و smoke-test نسخهٔ نصب‌شده ثبت شوند. این مرحله **انجام نشده است**.
